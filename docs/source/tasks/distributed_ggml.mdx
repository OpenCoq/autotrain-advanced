# Distributed GGML Training Set Synthesis

## Overview

The Distributed GGML Training Set Synthesis is a sophisticated pipeline that processes source code, documentation, and configuration files into a training set suitable for agentic cognitive grammar models. This implementation follows the architectural design specified in the GitHub issue for creating a transcendent training set pipeline.

## Features

### 🔍 File Discovery & Parsing
- **Recursive File Enumeration**: Automatically discovers files with specified extensions
- **Multi-format Support**: Handles Python (.py), Markdown (.md), YAML (.yaml/.yml), JSON (.json), and text files
- **Semantic Fragment Extraction**: 
  - Python: Functions, classes, docstrings with metadata (arguments, return types, decorators)
  - YAML/JSON: Configuration sections with key-value analysis
  - Markdown: Section-based parsing with header hierarchy
  - Text: Intelligent chunking based on fragment size limits

### 🕸️ Hypergraph Construction
- **Node Creation**: Converts fragments into hypergraph nodes with rich metadata
- **Concept Extraction**: Automatically extracts concepts (functions, classes, imports, configurations)
- **Relationship Mapping**: Creates multi-relational links between fragments and concepts
- **Meta-context Embedding**: Preserves file origin, line numbers, and type information

### 🧠 Tensorization & GGML Compatibility
- **Semantic Encoding**: Converts content to vector embeddings using hash-based deterministic encoding
- **Multi-dimensional Tensors**: Configurable embedding dimensions (64-2048)
- **Type-specific Processing**: Different encoding strategies for code, config, documentation
- **GGML Export Format**: Compatible tensor format with metadata preservation

### ⚡ Adaptive Attention Mechanisms
- **ECAN-inspired Scheduler**: Computes attention weights based on element centrality and similarity
- **Threshold Filtering**: Configurable attention thresholds for noise reduction
- **Metadata Boosting**: Frequency and type-based attention amplification
- **Normalized Weights**: Properly normalized attention distributions

### 🔀 Distributed Sharding
- **Semantic Clustering**: Groups related tensors for distributed processing
- **Configurable Shards**: Customizable number of distributed partitions
- **Round-robin Fallback**: Alternative sharding strategy for uniform distribution
- **Shard Metadata**: Complete tracking of tensor distribution

## Usage

### Basic Configuration

```json
{
  "task": "distributed_ggml",
  "data_path": "/path/to/your/repository",
  "project_name": "my-distributed-ggml-training",
  "file_extensions": [".py", ".md", ".yaml", ".json"],
  "tensor_dimensions": 512,
  "distributed_shards": 4
}
```

### Running the Training

```bash
# Using AutoTrain CLI
autotrain --config configs/distributed_ggml_training.json

# Using Python API
python -m autotrain.trainers.distributed_ggml --training_config configs/distributed_ggml_training.json
```

### Advanced Configuration

```json
{
  "task": "distributed_ggml",
  "data_path": "/path/to/complex/codebase",

  "file_extensions": [".py", ".md", ".yaml", ".yml", ".json", ".txt", ".rst", ".toml"],

  "distributed_shards": 8,
  "hypergraph_depth": 5,
  "semantic_clustering": true,
  "recursive_parsing": true,

```

## Output Structure

The training pipeline generates a comprehensive output directory:

```
project_name/
├── fragments_summary.json      # Fragment extraction statistics
├── hypergraph.json            # Complete hypergraph structure
├── training_manifest.json     # Training set metadata and manifest
├── validation_results.json    # Validation and quality checks
├── training_params.json       # Configuration used for training
├── USAGE.md                   # Generated usage documentation
├── tensors/                   # Unified tensor files
│   ├── node_embeddings.npy    # Node embedding tensor
│   ├── edge_embeddings.npy    # Edge embedding tensor  
│   ├── attention_weights.npy  # Attention weight tensor
│   └── *_metadata.json        # Tensor metadata files
└── sharded_tensors/          # Distributed tensor shards
    ├── shard_0/              # First shard
    ├── shard_1/              # Second shard
    └── ...                   # Additional shards
```

## Configuration Parameters

### Core Parameters
- `data_path`: Path to repository/dataset to process
- `project_name`: Output directory name
- `file_extensions`: List of file extensions to process
- `tensor_dimensions`: Embedding vector dimensions (default: 512)
- `distributed_shards`: Number of distributed partitions (default: 4)

### Advanced Parameters
- `max_fragment_size`: Maximum size of semantic fragments (default: 1024)
- `attention_threshold`: Minimum attention weight threshold (default: 0.1)
- `hypergraph_depth`: Maximum relationship depth (default: 3)
- `semantic_clustering`: Use semantic clustering for sharding (default: true)
- `recursive_parsing`: Enable recursive parsing of nested structures (default: true)
- `export_format`: Output format ("ggml", default)

### Integration Parameters
- `token`: Hugging Face API token for hub integration
- `push_to_hub`: Whether to push results to Hugging Face Hub
- `username`: Hugging Face username
- `log`: Logging method ("none", "tensorboard")

## Integration with GGML Models

The generated tensors are designed for direct integration with GGML-based models:

1. **Node Embeddings**: Represent semantic fragments as dense vectors
2. **Edge Embeddings**: Encode relationships between fragments
3. **Attention Weights**: Provide importance scores for training prioritization
4. **Metadata Preservation**: Maintains full traceability to source content

```python
import numpy as np

# Load node embeddings

# Load metadata
with open("project_name/tensors/node_embeddings_metadata.json") as f:

element_ids = metadata["element_ids"]
```
